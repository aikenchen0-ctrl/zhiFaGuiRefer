# 前沿 AI 记忆系统选型与整合决策

日期：2026-09-09  
范围：全域数字资产理解、索引与执行系统的 Agent 记忆、知识记忆和技能记忆。  
结论性质：设计决策，不代表已开始源码整合。

## 一、研究结论

近年的代表性论文和工程实践形成了六个稳定方向：

1. **上下文管理先于数据库选型**：上下文窗口是有限注意力预算，应该动态挑选最小的高信号内容，而不是把全部历史塞入提示词。[Anthropic：Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
2. **分层记忆**：工作上下文、可检索档案和持久状态应分开管理。MemGPT/Letta 将记忆管理视为操作系统式的虚拟上下文和显式记忆块。[MemGPT 论文](https://arxiv.org/abs/2310.08560)
3. **结构化表示优于纯摘要堆积**：Mem0 使用增量抽取、合并和图记忆；Memori 将对话转为语义三元组与摘要，并通过 BM25+向量混合检索减少上下文用量。[Mem0 论文](https://arxiv.org/abs/2504.19413)、[Memori 论文](https://arxiv.org/abs/2603.19935)
4. **时间和关系是一等字段**：Zep/Graphiti 维护事件时间、摄取时间、关系变化和历史版本，适合回答“当时”“后来”“曾经”的问题。[Zep 论文](https://arxiv.org/abs/2501.13956)、[Graphiti](https://github.com/getzep/graphiti)
5. **经验要经过反思和验证才能复用**：Reflexion 把反馈转为情节记忆；ReasoningBank 同时利用成功和失败轨迹抽取可泛化策略，再反馈给后续任务。[Reflexion 论文](https://arxiv.org/abs/2303.11366)、[ReasoningBank 论文](https://arxiv.org/abs/2509.25140)
6. **快速召回与深度回读应分路**：D-Mem 用质量门控在低成本向量检索和高成本全量推理之间切换，避免所有请求都执行昂贵的深度记忆读取。[D-Mem 论文](https://arxiv.org/abs/2603.18631)

Generative Agents 提供了仍然有价值的基本闭环：完整经历流、按新近性/重要性/相关性召回、周期性反思，再用于计划。[论文](https://arxiv.org/abs/2304.03442) A-MEM 则把记忆组织成带属性、关键词和动态链接的知识网络。[A-MEM 论文](https://arxiv.org/abs/2502.12110)

## 二、候选路线与取舍

| 路线 | 适合问题 | 主要优点 | 主要代价 | 本项目判断 |
|---|---|---|---|---|
| 分层上下文（Letta/MemGPT） | 长会话、跨会话恢复、上下文压缩 | 边界清楚、可编辑、可恢复 | 需要记忆调度器和持久事件日志 | 吸收为 `SessionContext` 机制 |
| 结构化长期记忆（Mem0/Memori） | 偏好、事实、联系人、用户习惯 | 低 token、跨模型、混合检索 | 抽取错误会污染事实；需冲突和置信度 | 作为 `PersonalMemoryService` 主算法参考 |
| 时间知识图（Zep/Graphiti） | 时间推理、关系变化、跨设备事件 | 历史关系和增量更新强 | 图数据库和实体消歧成本高 | 云端长期记忆增强层 |
| 记忆流+反思（Generative Agents/Reflexion） | 任务经历、失败复盘、策略改进 | 对行为学习直观、证据链完整 | 原始轨迹膨胀，反思可能幻觉 | 作为 Episode 到 Experience 的输入 |
| 经验自进化（ReasoningBank） | GUI 任务、网页任务、代码任务 | 同时利用成功和失败，减少重复探索 | 依赖可靠评判器，写入策略需审计 | 作为 Skill 候选生成和排序机制 |
| 双过程门控（D-Mem） | 查询成本和准确率冲突 | 普通请求快，难题才深读 | 需要质量评分和回退策略 | 作为 `MemoryRouter` 必备机制 |
| 编译式知识库（LLMWiki） | 资料、网页、文档、研究知识 | 可读、可审计、可引用、持续综合 | 编译延迟、陈旧和覆盖错误 | 作为 `KnowledgeSource`，不承载实时资产 |
| 在线参数记忆（TMEM/LoRA） | 固定模型快速适应单任务 | 行为改变快、无需反复检索 | 在线训练风险、回滚和灾难性遗忘 | 暂不采用，仅保留研究跟踪 |

## 三、对本项目的最终选型

### 3.1 不是单一记忆库，而是五层事实源

```text
L0 工作记忆       当前会话、最近观察、待确认动作
L1 个人长期记忆   偏好、稳定事实、联系人、跨会话经验
L2 资产记忆       文件/图片/视频/音频/文档的解析结果、向量、证据
L3 知识记忆       LLMWiki 主题页、实体页、引用图、冲突记录
L4 技能记忆       已验证的 SkillIR、参数、前置条件、失败修订
```

`Episode`、动作树和最近成功路径属于过程记录或执行缓存，不是事实记忆；只有通过验证、去重、冲突检查和晋升，才可以进入 L1 或 L4。

### 3.2 推荐组合

| 子系统 | 底座 | 吸收机制 | 不采用的部分 |
|---|---|---|---|
| 会话与上下文 | ClawGUI Session/Task 合同 | Letta 的分层记忆块、Anthropic 的压缩和可恢复事件流 | 不把上下文压缩结果当作唯一原始记录 |
| 个人长期记忆 | PowerMem 数据合同和生命周期 | Mem0/Memori 的结构化抽取、Graphiti 的时间关系、A-MEM 的动态链接 | 不直接复制完整云服务和固定图数据库 |
| 手机资产记忆 | Operit AssetIndex | X-OmniClaw 相册增量、PocketSearch 图片向量、D-Mem 门控检索 | 不把资产表与个人事实表合并 |
| 任务经验 | ClawGUI Episode | Generative Agents 记忆流、Reflexion 反思、ReasoningBank 成败对比 | 不直接把 LLM 自评结果晋升为 Skill |
| 技能记忆 | ClawGUI-Skills/SkillIR | KnowAct 验证、promote、失败修订和版本回滚 | 不保存未经回放的探索轨迹 |
| 知识记忆 | `KnowledgeSource` 端口 | LLMWiki 的增量编译、主题/实体页、引用回链、MCP | 不使用其桌面 UI、固定目录和小规模关键词索引作为生产核心 |

## 四、`MemoryRouter` 的查询策略

1. **精确路径**：日期、数量、文件属性、权限、版本和状态，先查结构化字段，不让向量相似度承担计算。
2. **快速路径**：并行执行全文、关键词、元数据、文本向量、图像向量和时间/关系召回，再用 RRF 或学习排序合并。
3. **质量门控**：依据召回覆盖度、来源一致性、时间冲突、证据数量和回答置信度评分；高置信度直接返回，低置信度进入深度路径。
4. **深度路径**：回读原始文件或完整 Episode，必要时调用云端大模型进行跨文档推理；结果必须带 `EvidenceRef`，不能只返回摘要。
5. **写回路径**：原始事件先进入候选区，经抽取、去重、冲突检测、权限检查和版本记录后，才写入长期记忆或 Skill。

## 五、端侧与云端的研究型分工

### 端侧

- 保存原始资产、URI、哈希、权限和增量游标；维护资产解析状态。
- 承担低延迟的 FTS、字段过滤、小规模 ANN、图片/文本轻量向量和证据定位。
- 保存当前工作记忆、设备能力、未上传的 Episode 草稿和离线待处理队列。
- 断网时完成资产查询和设备内动作；权限撤回立即使相关索引失效。

### 云端控制面

- 保存跨设备 Session、个人长期记忆、时间图、Skill 版本和审计记录。
- 承担重 OCR/VLM/ASR、批量重嵌入、长视频/PDF/Office 处理、Reranker 和全局图检索。
- 执行反思、经验融合、质量门控、Skill 晋升、LLMWiki 编译和离线评测。
- 向端侧返回最小充分的证据片段和幂等任务命令，不假设云端可以直接访问手机路径。

## 六、必须建立的评测集

不能只测“能否召回相似文本”，至少建立以下分项：

| 评测维度 | 参考基准/方法 | 本项目指标 |
|---|---|---|
| 长期会话记忆 | [LoCoMo](https://arxiv.org/abs/2402.17753) | 单跳、时间、多跳、开放域、多模态问答准确率 |
| 记忆层级与长程恢复 | [LongMemEval](https://arxiv.org/abs/2410.10813)、[LongMemEval-V2](https://arxiv.org/abs/2605.12493) | 跨会话召回、时间顺序、知识更新、冲突处理和拒答 |
| 经验迁移 | [ReasoningBank](https://arxiv.org/abs/2509.25140)、[AGENTCL](https://arxiv.org/abs/2606.02461) | 成功率增益、失败重复率、任务步数、Skill 晋升精度 |
| 资产检索 | 自建手机资产集 | 文件覆盖率、证据定位准确率、跨模态召回、增量延迟 |
| 运行成本 | D-Mem 双路径思想 | p95 延迟、端侧电量、上传字节数、云端 token/算力 |

注：LongMemEval 与 LongMemEval-V2 的数据规模、任务定义和评测脚本不同，正式评测前应固定数据集版本、模型版本和可复现实验脚本；不能把单一榜单分数当作真实手机记忆效果。

## 七、阶段性决策

1. **第一阶段**：在 Operit 端侧先实现 `AssetIndex`、工作记忆和快速/深度双路径查询；不引入在线 LoRA，不把完整图数据库放入手机。
2. **第二阶段**：在 ClawGUI 控制面接入 PowerMem 风格的个人长期记忆、时间关系和跨设备查询；以 `MemoryRouter` 统一召回。
3. **第三阶段**：接入 LLMWiki `KnowledgeSource`，把文档、网页和研究材料编译成可引用知识页；知识页必须回链原始 `AssetId`。
4. **第四阶段**：接入 ReasoningBank/KnowAct 的成败经验和验证晋升，形成 GUI 轨迹到 Skill 的闭环。
5. **暂缓事项**：在线参数记忆、全量原始对话上云、端侧完整知识图谱、未经门控的自动记忆写入。

### 最终判断

最稳妥且效果上限最高的选择是：**Operit 负责端侧资产记忆，ClawGUI 负责控制面和长期记忆，PowerMem 提供记忆生命周期，Graphiti/Zep 提供时间关系，Mem0/Memori 提供结构化抽取，D-Mem 提供查询门控，ReasoningBank+KnowAct 提供经验到 Skill 的晋升，LLMWiki 提供知识编译。**

这套组合比直接照搬 Letta、PowerMem 或 LLMWiki 任一项目更复杂，但能避免把实时资产、个人事实、知识页面和可执行技能混成一个高耦合系统，符合高内聚、低耦合目标。
